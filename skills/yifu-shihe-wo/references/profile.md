# 穿衣档案

人的信息只收一次，整理成一张卡，以后每件衣服都用它。档案和衣服的属性卡（`attributes.md`）用同一套坐标，判断时一项一项对。

## 第一次怎么收

第一次用时按 `onboarding.md` 走：先示范，再请用户填那张分层的数据表（身高、体重要问到；裤长、腰围、胸围知道更好；再细是合身衣服的平铺尺寸；最后是喜欢的品类、场合、方向）。

- 用户填了多少就用多少。缺的不追着问，照下面「怎么收」的规矩，每轮最多问 2 个。
- 这些数只用来判断合不合身、长度落在哪，不评价身材。用户问起，就这么说。

## 两种尺寸

- **合身尺寸**（成衣尺寸）：衣服平铺量出来的数，和商品的尺码表是同一种数，能直接一项一项对，最好用。
  - **按品类分开记**：夹克、西装、大衣、衬衫、针织、裤子、裙子各记各的，判断时只和同一品类比。短夹克的衣长、西装的后中长（从后领中间量下来）不是一回事。
  - 衬衫加记领围和领座高（领座是领子立起来那一截）。
  - 裤子加记前浪（腰头到裆）、后浪。前浪决定裤腰落在哪：前浪短的是低腰。
  - 同一项可以记一个范围（肩宽 38～39），也可以记一句经验（「衬衫胸围 100 以下才修身」）。
- **净体尺寸**（量身体）：不能直接对尺码表，要加上放松量。成衣胸围大约是净胸围加：修身 6～10，常规 10～16，宽松 16 以上（粗估，男装衬衫的常规款放得更多）。穿在腰上的裤子，成衣腰围和净腰围差不多，或者大一两厘米。只给了净体尺寸的，尺码判断的可信度最多给「中」。
- **体重**：只在什么尺寸都没有的时候，用来粗推一下偏大还是偏小。身高体重一样的两个人，肩宽、腿长可以差得很远。

## 怎么收（照片和问答）

用户没填的项，先从照片看，照片看不出来的才问。每轮最多问 2 个，先问会改变结论的。

| 项 | 先看 | 看不出来再问 |
|---|---|---|
| 颜色 | 自拍：自然光、不开美颜、手机不挡脸，素颜最好 | 金饰和银饰，哪个戴着更显气色？晒了以后先变红还是先变黑？纯白和米白的 T 恤，哪件穿着脸更干净？ |
| 身高 | — | 必问，判断长度落点要用 |
| 线条 | 全身照：别人帮拍、站直、正面、穿贴身一点的衣服 | 肩和胯哪个宽？腰细的地方明显吗？上身和腿，哪段显得长？ |
| 气质 | 自拍和全身照：骨架和五官大小、轮廓圆润还是有棱角 | 一般不问，看不出来就在档案里写「待定」 |
| 骨架 | 全身照：上身厚薄、重心高低、骨骼关节明不明显 | 挺括合身、软塌垂顺、宽松粗糙，哪种衣服别人最常夸？哪种穿上像被衣服吞掉？ |
| 场合 | — | 这件打算什么时候穿？一周大概几天上班、几天休息？ |
| 衣橱 | — | 最常穿的三四件是什么？ |
| 方向 | — | 想往什么方向穿？有没有绝对不碰的？ |
| 合身尺寸 | — | 问尺码时再要，填法见上面的模板 |

不要一次把表里的问题都抛出去。用户只想快速问一件，就先判断这一件，档案慢慢补齐。

照片的坑（光线、美颜、妆、染发、手机挡脸）见 `color.md`，机位的坑（俯拍、坐着拍、裁掉下摆）见 `product-input.md`。

## 档案卡

第一次完整判断之后，把用户填的和看出来的整理成这张卡发给用户，提醒用户存下来：下次直接贴过来；用的 AI 有记忆功能的话，让它记住。

```
【我的穿衣档案】
颜色：偏冷、偏浅、偏柔，对比中（可信度：中。依据：自拍，加上戴银饰更显气色）
身高：162　体重：50
常穿的码：上衣 S，裤子 26，鞋 37
线条：肩和胯差不多宽，腰线明显，腿比上身长
气质：量感小，偏直，偏静
骨架：曲线型为主，带一点直线型
喜欢的品类：衬衫、针织、直筒裤
常穿场合：通勤一周五天，周末看展、逛街
衣橱里常穿：白衬衫、黑色直筒西裤、浅色牛仔外套
想要的方向：更利落一点
不碰：短裙、亮片
合身尺寸（平铺量的成衣尺寸）：外套肩宽 38～39，衬衫胸围 96 左右、领围 36，裤子前浪 28、裤长 95、大腿围 54 以上
```

- 看不出来、用户也没填的项写「待定」，不要编。
- 每项标清是用户填的、还是从照片看出来的；对不上的时候先信用户填的。
- 以后的判断里发现档案和实际对不上（比如试衣照里银色反而压气色），在结论卡后面提一句「档案里这条可能要改」，给出改法。
