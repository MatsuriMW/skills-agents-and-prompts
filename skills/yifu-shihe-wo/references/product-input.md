# 衣服的信息从哪来

## 链接

商品页的内容是页面脚本跑完才出来的，只抓网页源码的话常常只拿到一个空壳或一个标题。用真浏览器打开的话：抖音商城、小红书的商品页不登录也能看；淘宝、拼多多要先登录；1688 有时要拖滑块。淘口令（「复制这段话打开淘宝」）不是网址，要从里面找出 `https://` 开头的那一段才能打开；口令里的商品标题可以当线索，但不能当证据。

- 能打开、看得到图和参数：照常用，按下面「要哪几张截图」的顺序去页面上找对应的东西。
- 打不开、或者只有标题：直说「这个链接我读不到内容」，请用户发截图（见下）。**不要从标题里的「显瘦」「高级感」「百搭」推断任何东西**，那是卖家写的。

## 要哪几张截图

按重要性排，有前两张就能先判断：

1. **主图或模特图 1–2 张**：看颜色、版型、长度。
2. **买家秀 1–2 张**：自然光、普通身材，颜色最接近收到的实物。主图和买家秀颜色差得多时，信买家秀。
3. **尺码表**：衣长、肩宽、胸围、腰围、裤长、裙长。算长度落点要用它。
4. **面料成分**：详情页里「面料」或「成分」那一栏。值不值那一问要用。
5. **模特信息**：模特身高、体重、穿什么码。

缺哪张就在「依据」里写缺了哪张。

### 读尺码表

衣长、肩宽、胸围、袖长、裤长这些数，**只从尺码表来**，图片只用来看颜色、版型和细节。

- 先找用户会穿的那个码那一行；拿不准穿哪个码、或者夹在两个码之间，相邻两行都读，拿来比。
- 看清量法：衣长是从肩颈点量还是后中长；胸围、腰围是平铺（要乘 2）还是周长。表头没写的，按表里数的大小判断（胸围五十几的多半是平铺），判断不了就在「依据」里说。
- 只有身高体重推荐码（「170/65 穿 M」）、没有具体尺寸的，当参考，不当数据；请用户截带尺寸的那张表。

## 商品图的坑

- 主图常被调亮、调饱和，白底图尤其偏亮。看颜色先打个折扣，有买家秀以买家秀为准。
- 模特大多 170 以上，衣服常在后背夹过。长度不要按模特图目测，按尺码表和用户身高算（见 `line.md` 的长度落点）。
- 同一件的不同颜色放在一起的那张图，可以拿来比颜色之间的冷暖深浅，比单看一张准。

## 试衣照

人穿着这件拍的照片，是最好的证据：脸色有没有被压下去、长度落在哪、腰线在哪，都能直接看。前提是机位对。

### 先看机位

| 照片 | 能看什么 | 不能看什么 |
|---|---|---|
| 别人帮拍、手机在腰的高度、站着、全身入镜 | 全都能看 | — |
| 对着镜子自拍，手机举在脸前 | 肩线、袖长、面料、搭配、长度大概落在哪 | 比例：这是俯拍，腿显短、上身显长，不能据此说「截短了腿」；颜色：脸多半被手机挡住 |
| 坐着拍、低头往下拍自己 | 颜色（不看脸的部分）、面料、搭配 | 长度、比例、合不合身 |
| 下摆被裁掉、只拍到大腿 | 上半身的版型 | 衣长落点 |

不能看的那几项，照片里看起来再明显也不下结论：长度和比例改用尺码表加身高或合身尺寸算（见 `line.md`），颜色改用档案，都没有就在结论卡里写「—」，说要补什么。

- 试衣间的灯通常偏暖偏亮，脸会显得比平时好。颜色判断的可信度最多给到「中」。
- 想拍得能用：请人帮拍，站远一点拍全身，正面，手机放在腰的高度；再拍一张这件贴着下巴的半身，手机别挡脸。有条件就到窗边自然光下拍。

## 参考图（「想找这种款」）

用户发来模特穿的图、别人的穿搭、杂志图，问「这种款适合我吗」「我想买这样的」，问的是一类款式，不是这一件，而且图里的身材不是用户的（模特的性别、身高都可能和用户不一样）。

1. 先判断这种款和用户合不合：颜色、气质、线条方向，照四问走，不拿模特的比例判断用户。
2. 再把它换算成用户该找的数，按这些数去挑：
   - 衣长：图里下摆落在模特身上哪里（腰、胯、臀下沿……），用 `line.md` 的落点表换算成用户身高下的衣长；有合身尺寸的，直接用合身尺寸。
   - 肩：正肩、落肩还是插肩，肩宽按合身尺寸。
   - 领型、门襟、口袋这些看得见的细节。
   - 面料厚薄和硬挺程度。
3. 结论卡的「更适合你的」换成「按这些数去找」，列成一行。

用户是男生、参考图是女装（或者反过来）时，换算成对应的男装（女装）尺寸和版型去找，不评论这件事。
