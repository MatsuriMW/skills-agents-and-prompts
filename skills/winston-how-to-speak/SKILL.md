# Winston 演讲法：把一场讲设计出来

方法论来自 MIT Patrick Winston 教授《How to Speak》（2018）。**细节、原话、时间戳在 `references/winston-lecture-digest.md`，需要举例或确认原文时去读它。**

## 一句话底层信念

> 人生成功主要由三件事决定：**说、写、想法的质量**（按此顺序）；
> 而说的能力 ≈ **K（知识）+ P（练习）+ T（天赋）**，**T 非常小**。

所以：演讲不是天赋，是**可以靠知识和练习堆出来的技术**。给用户干活时，态度是"这套东西有具体招式，我们一条条改"，不是"你要自信一点"。

## 铁律（先记住这六条）

1. **开场不用笑话，用「赋能承诺」**：告诉听众这场结束后他们会知道哪些现在不知道的东西。
2. **说三遍**：任何时刻约 20% 的人在走神。重要主张要循环出现，不是啰嗦。
3. **给想法建围栏**：永远说清你的东西和别人的东西差在哪。
4. **一个语言处理器**：听众要么读、要么听，**不能同时**。字多 = 没人听你。
5. **幻灯片是调味品，不是主菜**：它用来 exposing，不用来 teaching。
6. **最后一页是 Contributions，最后一句话不是 Thank you。**

## 工作流

### 0. 先问清四个问题（不要凭空开写）

- **目的是哪一种**：informing（教/讲座）还是 persuading（说服：答辩、job talk、拿资源、让人记住你）？这决定整套结构。
- **听众是谁、几分钟**（5 分钟 / 20 分钟 / 一小时，差别是结构性的）。
- **场地条件**：灯能不能全开、能不能提前踩点、预计上座率。
- **有没有现成稿 / PPT**：有就先做「审查」（第 4 步），别重写。

缺信息就问，别脑补。但问一次即可，剩下按合理假设往下做并标注。

### 1. 定「赋能承诺」（开场）

写一句话：**"这（XX 分钟）结束后，你会 ______（现在还不会 / 还不信）。"**

- 必须是**听众视角的所得**，不是"我将介绍……"这种目录式废话。
- 承诺要能被兑现：结尾的 Contributions 要和它呼应。
- 开场顺带**表达热情**（passion 是被证实最能激励人的东西之一）。
- 笑话？**留到结尾**。开场听众还在调你的声音参数，笑话必砸。

### 2. 搭骨架

**通用技术报告骨架（"三明治"）**

```
[第 0 页] 合作者 / 团队 —— 放第一页，不是最后一页
[开场]   赋能承诺 + 热情
[5 分钟内] Vision：有人在乎的问题 + 你方法里"新"的那一点   ← job talk 生死线
[主体]   达成愿景需要哪几步（不必全做完，但要说清"需要做什么"）
         每一步：先建围栏（与别人的区别）→ 演示/证据 → 口头标点小结
[结尾]   Contributions（与"步骤"形成镜像）
[最后一句] 笑话 / 向听众致意 / 祝福式收尾 —— 不是 Thank you
```

**教学型（informing）骨架**

```
赋能承诺 → 循环讲解（讲三遍）→ 道具/现场演示 → 故事 → 收束
```

教学的最高目标是**教人怎么想**。Winston 的答案：人是 storytelling animals，所以教思考 = **给故事 + 该问的问题 + 分析故事的机制 + 拼接故事的方法 + 判断故事可靠度的办法**。

**激励人的三条实证**：告诉对方"你能行"；让对方**用新方式看到一个老问题**；**讲的人自己表现出热情**。

### 3. 埋技巧（至少用上四条）

| 技巧 | 做法 | 检查点 |
|---|---|---|
| **Cycling 绕圈** | 核心主张在开场/中段/结尾各出现一次 | 能不能只听结尾也拿到主张？ |
| **Build a fence 建围栏** | "我的 X 看起来像 Jones 的 Y，但他是 O(n²)、我是 O(n)" | 每个关键概念有没有"它不是什么"？ |
| **Verbal punctuation 口头标点** | 报数字、报大纲、报接缝："第一/第二/接下来我们离开 A 进入 B" | 走神 3 分钟的人能不能重新上车？ |
| **Ask a question 提问** | 难度适中（不 obvious 也不 impossible），**问完敢停 7 秒** | 每 10–15 分钟有一次互动点？ |

### 4. 审查幻灯片（有现成 PPT 时先做这一步）

**宏观：打印出来摊开看。** 让对方把每页打印出来平铺在桌上——一眼就能看出"太重"：字太多、留白不够、图不够。好的一套应该"**有空气**"。

**逐页红线**

- [ ] 每页字数：能删就删。**去掉背景装饰 → 多余的字 → logo → 标题**（标题不必挂屏幕上）。
- [ ] 字号：**裸奔下限 30–35pt，40–50pt 才算舒服**。字号小的真正危害是你会用它塞更多字。
- [ ] 不念幻灯片。屏幕上有的字，你嘴里换成屏幕上没有的话。
- [ ] 讲者不要站得离屏幕太远（避免"网球赛"来回看）。
- [ ] **不用激光笔**——一转头就丢掉目光接触。要指就**在图上画箭头**，说"看箭头指的那个"。
- [ ] 那种"复杂到爆炸"的图（hapax legomenon）**一场只允许一张**。
- [ ] 需要听众读的字：留**停顿时间**让人读完。
- [ ] 结尾页是 **Contributions**，不是 Conclusions / 致谢 / Thank You / Questions?。

**加分**：能用**实物道具**就用——共情镜像（empathetic mirroring）让听众"感觉自己在操作"，这是幻灯片永远做不到的；现场板书/手绘的速度 ≈ 听众吸收速度，翻页永远太快。

### 5. 让它被记住：Winston's Star（五个 S）

给用户的工作/报告包装记忆点，缺一个就掉一个量级：

| S | 问什么 | 例子（Winston 的"拱"） |
|---|---|---|
| **Symbol 符号** | 有没有一个能画出来的视觉符号？ | 拱 |
| **Slogan 口号** | 有没有一句能当把手的短语？ | "One-shot learning" |
| **Surprise 反直觉** | 有没有一个"居然是这样"的点？ | 不需要一百万样本，一个就够 |
| **Salient idea 凸出的点** | 有没有**扎眼**的想法？（不是"重要"，是"凸出来"；好想法太多反而没人知道你在讲啥） | Near miss（近失例） |
| **Story 故事** | 你怎么做到的、为什么成立、为什么重要？ | — |

> 收一句 Winston 的话给用户：**"你的想法就像你的孩子，别让它们衣衫褴褛地走进世界。"**

### 6. 场景手册

**A. 答辩 / 口试 / 评审**
失败的两大原因：**没 situate + 没 practice**。
- *Situating*：把工作放进**时间 / 地点 / 领域**坐标——"这个问题全世界都在追，过去 30 年没进展，大家都想要解，因为它牵动一大堆别的东西"。
- *Practice*：**不要把稿子给懂你工作的人看**，他们会**幻觉出你根本没讲的东西**（导师尤其不适合帮你 debug 演讲）。要找**不懂你工作的人**当毒舌观众。

**B. Job talk / 求职报告 / 立项汇报**
**5 分钟内**必须同时建立两件事：**vision**（有人在乎的问题 + 你的新东西）和 **done something**（你确实做成了）。做不到就已经输了。结尾**列举 contributions**，与前面的"步骤"镜像。

**C. 长时间讲座 / 公开课**
- 时间争取**上午 11 点**；场地**灯全开**（"你没法透过闭着的眼皮看幻灯片"）；**提前踩点**；场地至少要**坐满一半以上**（空场会让人分心）。
- 心理预演：**想象全场坐满漠不关心的农场动物**——真实情况再差也不会比这更糟。

### 7. 收尾

- 最后一页 **Contributions**，提问和散场时一直挂着。
- 最后一句话四选一：**讲个笑话**（此时大家已适应你的声音）/ **向听众致意**（"我在乎这个地方和这段时间……"）/ **祝福式 benediction** / **仪式性收尾**（明确宣告结束的信号）。
- 禁忌：**"Thank you"、"Thank you for listening"**——那暗示大家是出于礼貌才留到最后。掌声起来后无声嘴型致意可以，但最后一句话不能是它。
  > "大家都这么做，不代表这是对的。"

## 交付格式

给用户输出时按这个顺序，别写成长篇散文：

1. **赋能承诺**（一句话）
2. **骨架**（带时间分配的要点列表，标注 vision / 步骤 / contributions 出现在第几分钟）
3. **记忆点：五个 S**（哪个已有、哪个缺、建议补什么）
4. **幻灯片改造清单**（具体的、可勾选的问题列表）
5. **开场白 + 结尾原话**（可直接照着说的两句）

审查已有材料时，先给**红线问题 Top 3**（最致命的），再给完整清单。
