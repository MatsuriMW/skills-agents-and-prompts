# 文章稿：书面稿默认写法

他写东西的规则分三层，这个 skill 是第一层的入口：

1. **文章稿风格提示词（总章）**：所有书面稿都按它；口播稿也拿它打底。
2. **koubo-writer + 口播稿风格提示词**：只有他说要做成视频 / 口播稿时才叠加。
3. **human-writing**：通用纪律（材料不够不灌水、事实要核、不写翻案腔），和前两层冲突时听前两层。

## 三种常见情况

**他给了草稿或要点，让你写成文章**（最常见，也是 claude.ai Project 原来的用法）：照总章第一部分的框架来。先从草稿里找出能当开头的具体情景、人物例子或者矛盾现象，一两句给出答案，再按「第一、第二、第三」一个一个展开论点，合适就落到能操作的建议，最后另起「信源」。草稿内容太杂太多时，用排比并列集中讲一遍。

**从主库的选题写成文章**：流程照 koubo-writer 的第 1–3 步和第 6 步走（找选题 → 按意思检索主库备料 → 素材够不够，不够就问他或写短 → 存稿并回链选题页），读 `~/.claude/skills/koubo-writer/SKILL.md` 里对应的部分。不同的地方有三处：
- 不做视频层，不画情绪线，不标 `[!画面]`；需要配图的地方标 `> [!配图]`，写法见 `~/.claude/skills/koubo-writer/references/video-layer.md` 第五节「长文的配图和节奏」。
- 风格只读总章，不读口播稿风格提示词。
- 存到稿子库 `~/Documents/Obsidian Vault/<标题>.md`，属性写 `形式: 文章`。

**改他已有的一篇文章**：先弄清楚他要改的是内容、结构还是文风。改文风就逐段对照总章；不覆盖原文，另存 ` v2`、` v3`。

## 写完自查

先跑机械检查，它查翻案句、叠甲开场、加粗过多、碎成一行一段，以及设问、devil's advocate、「信源」有没有：

```bash
python3 ~/.claude/skills/koubo-writer/scripts/script_lint.py 稿子.md --form article
```

然后人工对照总章第一部分，逐条过：

- 至少一处辛辣的嘲讽或带立场的暴论，而且够敢
- 至少一句设问或反问（「那为什么……」「你知道为什么……」「……对吧？」）
- 至少一句 devil's advocate（「那有人就会问了」「当然我这样说有点绝对」），是真在压测论点，不是摆设
- 核心论点加粗，一节最多一句
- 外国人名、专业术语在中文后面括号标英文原名；论文标作者和年份
- 文末另起「信源」，论文、理论、事迹、数据的出处都在；拿不准的挪到「待核」，不留在正文
- 除了阐释论点的地方，矫饰性表达全部删掉；比喻在承担解释功能
- 没有煽动和贩卖焦虑
- 标点照 GB/T 15834《标点符号用法》

human-writing 那边只借两条纪律：材料不够就研究、追问或写短，不灌水；事实、引语、数据要核。它的检查脚本 `~/.claude/skills/human-writing/scripts/check_prose.py` 可以再跑一遍查翻案腔，别的报警以总章为准。

## 交稿

在稿子库里写的，或者他说要存的：存进稿子库，属性带 `作者: AI 初稿`（他改过认领后才去掉），新增或改名之后重跑 `bash "$HOME/Library/Mobile Documents/iCloud~md~obsidian/Documents/马自立/scripts/index-obsidian-vault.sh"`。其他情况直接在对话里给全文。

交稿时说清楚：哪几处是你补的通识或例子（请他核对或换成自己的话），机械检查报了什么、怎么处理的，哪些数字放进了「待核」。

他反复提的同一类修改意见，问他要不要写进总章第二部分——那是这套规则的长期记忆。
