# 文章稿：书面稿默认写法

他写东西的规则分三层，这个 skill 是第一层的入口：

1. **文章稿风格提示词（总章）**：所有书面稿都按它；口播稿也拿它打底。
2. **koubo-writer + 口播稿风格提示词**：只有他说要做成视频 / 口播稿时才叠加。
3. **human-writing**：只管内容准确、可溯源、不幻觉（事实、引语、数据要核，材料不够不灌水）；文风一律不听它。


**每次都重新读**，他会改。第一部分是 claude.ai Project「文章稿」的原文，是硬要求；第二部分是细则和例句，冲突时听第一部分。

**总章不定结构。** 文章怎么搭、从哪进、分几块、落在哪，是和他沟通聊出来的，不要自己套模板。总章管的是风格、细节和整体约束（木遥式的推理和用词、设问、devil's advocate、加粗论点、多个论点用第一第二第三一个一个讲、信源……）。他要「更文白一点」时，再读同目录的《文白交杂风格提示词》。

## 点名文体时，叠一层文风 skill

他说这篇是技术写作、社会评论或商业分析时，总章打底，再读对应的文风 skill（都在 skillshare 的 `styles` 分组，原样下载的）：

|---|---|---|
| 技术写作 | `~/.claude/skills/zh-tech-writing/SKILL.md` | 平实、具体、短句，AI 腔清单 |

| 商业分析 | `~/.claude/skills/strategist-voice/SKILL.md` | Damodaran、Ben Thompson 式的分析师文风，脚注引用 |

**冲突时听文风 skill**，它就是用来改掉总章里不适合这种文体的地方的。只有一条底线不让：事实、引语、数据要真，拿不准的进「待核」，不编。`op-ed-writer` 和 `strategist-voice` 是英文写的，照它们的写作规则写中文；只对英文成立的规则（比如禁用 em dash）换成总章里对应的中文标点规范。动笔前把这篇里两边冲突、你打算听文风 skill 的地方列给他看一眼。

他没点名文体，就只按总章写。

## 四种常见情况

**他给了草稿或要点，让你写成文章**（最常见，也是 claude.ai Project 原来的用法）：结构跟着他的草稿和你们聊出来的思路走。草稿里没定、你又拿不准的（从哪进、先讲哪个论点、落在哪），先问他一句，不要自己定一个框架套上去。写的时候守总章的约束：多个论点用「第一、第二、第三」一个一个讲完再讲下一个；草稿内容太杂太多时，并列起来集中讲一遍；最后另起「信源」。

**从主库的选题写成文章**：流程照 koubo-writer 的第 1–3 步和第 6 步走（找选题 → 按意思检索主库备料 → 素材够不够，不够就问他或写短 → 存稿并回链选题页），读 `~/.claude/skills/koubo-writer/SKILL.md` 里对应的部分。不同的地方有三处：
- 不做视频层，不画情绪线，不标 `[!画面]`；需要配图的地方标 `> [!配图]`，写法见 `~/.claude/skills/koubo-writer/references/video-layer.md` 第五节「长文的配图和节奏」。
- 风格只读总章，不读口播稿风格提示词。
- 存到主库 `稿件/<标题>.md`，属性写 `形式: 文章`；选题页 `稿件:` 加上 `"[[稿件/<标题>]]"`。

**写推文、小红书这类短帖**：风格照样按总章（木遥式的冷静和准确、设问、加粗核心论点、术语标英文、不煽动焦虑），但总章第一部分里有两条不强求：文末「信源」和「每篇至少一句 devil's advocate」。要用的数据或引语，出处能放进正文就放一句，放不下的交稿时在对话里另外列给他。长度和格式跟着平台走（推文一条或一串，小红书标题加正文），不要把长文的结构硬塞进来。不存进 `稿件/`，除非他说要存。

**改他已有的一篇文章**：先弄清楚他要改的是内容、结构还是文风。改文风就逐段对照总章；不覆盖原文，另存 ` v2`、` v3`。

## 扩写和头脑风暴时，翻他的表达与典故素材库

总章第二部分「表达与典故素材库」一节写了怎么用。动笔扩写、或者和他头脑风暴方向之前，按这段在讲什么去检索：

```bash
python3 ~/.claude/skills/koubo-writer/scripts/sem_search.py "这段在讲什么" "换个说法" --scope expr --top 15
```

挑贴得上的适当用：自写的可以直接用；摘抄的当引用并注明出处，或者只借句式；不确定、AI 补充的先问他。**拿不准要不要用、用在哪，就问他**：把候选原文、来源标记和打算放的位置列出来，让他选。交稿时说一下用了哪几条。

## 写完自查

先跑机械检查，它查翻案句、叠甲开场、加粗过多、碎成一行一段，以及设问、devil's advocate、「信源」有没有（短帖缺 devil's advocate 和「信源」的两条报警不用管）：

```bash
python3 ~/.claude/skills/koubo-writer/scripts/script_lint.py 稿子.md --form article
```

然后人工对照总章第一部分，逐条过（短帖跳过 devil's advocate 和「信源」两条）：

- 判断鲜明，但语气冷静：没有嘲讽、暴论、脏字，排比最多在情绪最高处用一次，只排词和句式
- 罗列多个例子、对比冲突放在开头；人物对撞放在开头或全文最核心的论点上；其余地方少放，没有一口气排开一串人物、事例的段落
- 用设问推进（「为什么呢？」「但这是……么？」），问在读者心里正好会冒出来的地方
- 至少一处 devil's advocate，用「这当然不是说……」、括号里的限定、「或者再确切一点说」带出来，是真在压测论点，不是摆设；没有「那有人就会问了」这类套话
- 冷僻成语和文言词用得准，一段最多一两个，换成白话要多写半句才算准
- 核心论点加粗，一节最多一句
- 外国人名、专业术语在中文后面括号标英文原名；论文标作者和年份
- 文末另起「信源」，论文、理论、事迹、数据的出处都在；拿不准的挪到「待核」，不留在正文
- 除了阐释论点的地方，矫饰性表达全部删掉；比喻在承担解释功能
- 没有煽动和贩卖焦虑
- 标点照 GB/T 15834《标点符号用法》

human-writing 只用来保证内容准确、可溯源、不幻觉：材料不够就研究、追问或写短，不灌水；事实、引语、数据要核，每条找得到出处。它现在只剩这部分，文风以总章为准。
