# koubo-writer：选题 → 成稿

## 两个库

| | 路径 | 放什么 |
|---|---|---|
| 主库 MAIN | `~/Library/Mobile Documents/iCloud~md~obsidian/Documents/马自立` | 选题页（`选题/`，`type: 选题`）、日记（`日记/`）、概念 / 人物 / 书、素材库、风格提示词 |
| 稿子库 DRAFTS | `~/Documents/Obsidian Vault` | 正在写和写完的稿子。只放稿子 |

稿子永远写进 DRAFTS，素材永远从 MAIN 读。MAIN 里的日记和笔记是他的原始记录，写稿过程中不要改它们（选题页的属性除外，见第 6 步）。

## 为什么要有这套流程

他的素材是几年里零散记下的日记块，写稿时最难的是想起自己记过什么；而 AI 直接写出来的稿子，观点是模型的、腔调也是模型的。所以这套流程的重心有三个：**稿子里的每个判断和例子尽量回到他自己记过的东西上**；**声音照他的风格提示词来**；**稿子是给视频用的，写每一段的时候就要知道观众这时候看什么、什么感觉**——画面和节奏等写完再补，只能补成贴在文字上的装饰。素材不够的地方宁可问他、宁可写短，也不要用通识和漂亮话补齐——补出来的那部分正是他录的时候会觉得「这不是我会说的话」的地方。

## 流程

### 1. 找到选题

- 用户给了选题名：读 `MAIN/选题/<名字>.md`；没有就看 `MAIN/已发表/<名字>.md`（发表过的选题会被归档到那里，这时是把已发表的文章改成另一种形式，原文是他自己的话，当底稿用，尽量保留他的原句）。还找不到就全库按文件名找。属性里看 `状态`、`形式`、`主题`、`稿件`（已有的稿子，相对 DRAFTS 根目录）、`用到的素材`。
- 有 `稿件`：先读已有的稿子，问清楚是改这一版还是另起一版。不要覆盖已有的稿子。
- 选题是日记里的一个块（带 `[[视频选题]]` / `[[文章选题]]`）：那一块和它的子项就是选题本身。
- 没说形式就问一句：口播（录视频 / 播客）还是长文（博客 / Newsletter）。两种的风格提示词不通用。

### 2. 备料

先看有没有现成的：`MAIN/选题/_采访/<选题>/` 下的 `00-素材包.md`（选题正文 + 全部反链）、`01-完整采访记录.md`、`02-采访分析与知识整理.md`、`写作方案.md`。有 `02` 的，观点以它为准；有 `写作方案.md` 的，结构以它为准。

然后按意思检索主库，把选题拆成 4–8 个不同的说法分别查（换词、换角度、反面的说法都要有——他记的时候用的词和现在想的词往往不一样）：

```bash
python3 ~/.claude/skills/koubo-writer/scripts/sem_search.py "说法一" "说法二" "说法三" --top 20
python3 ~/.claude/skills/koubo-writer/scripts/sem_search.py "……" --scope journal --since 2025-01-01
```

它和 Obsidian 里写作模式用的是同一份向量缓存，秒级返回；Ollama 没开会报错，这时改用关键词检索 `python3 ~/.claude/skills/vault-ask/scripts/vault_search.py 词1 词2 …`。专有名词、人名、书名用关键词检索更准，两种都跑一遍最稳。

命中的块回原文读上下文（`路径:行号`），再筛。筛的时候分清两种东西，因为用法不同：

- **他自己的话**：短句、第一人称、问句、任务旁的感想。可以直接当稿子里的判断和经历。
- **摘录**：`>` 引用、带作者或书名出处的、整段书摘。只能当论据引用并说明出处，不能写成他的观点或亲身经历。拿不准的，列出来问他。

库里标着 AI 生成的东西（`Wiki/` 下带「（wiki）」的页面、开头写「素材来自…」的旧稿）只当线索，不当素材。带 `[[宝a]]`、`[[宝]]` 的块是私事，不进稿子。

### 3. 素材够不够

把备到的料摆出来看：有没有一个能当开头的具体场景或人；核心判断背后有没有他自己的经历或他记下的例子；有没有能查的数字、年份、人名。

不够的时候，告诉他缺什么，然后二选一：

- 问他。一次一个问题，从说得不清、互相矛盾、只起了个头的地方问起。要系统地采访就用 `qws` skill（采访文件存到 `MAIN/选题/_采访/<选题>/`）。
- 他不想答，就把稿子写短，缺料的那一节直接不写，在交稿时说明。

### 4. 定方案（写之前和他对一次）

用一条消息给他看，等他点头或改：

- 一句话主张（听完能复述的那句）
- 讲给谁、对方听完得到什么
- 骨架：每节一句话 + 这一节用哪几条素材（带出处）
- **情绪线**（口播 / 视频稿必须有）：每段的时间、这段干什么、观众此刻的反应、强度 1–5、主要画面。怎么设计见 `references/video-layer.md` 第二节——先读它再画这张表
- 开头用什么场景，结尾落在哪（全片最高点放在结尾前）
- 打算舍掉的料

他想被盘问写作方案时，按 grill-me 的方式一次问一个问题、每问都给出你推荐的答案，结论写进 `MAIN/选题/_采访/<选题>/写作方案.md`。

### 5. 写

**每次都重新读风格提示词**，它们在主库里，他会改：

- 口播稿 / 播客稿 / 演讲稿 → `MAIN/写作与创作/口播稿风格提示词.md`
- 博客 / Newsletter / 长文 → `MAIN/写作与创作/书面语风格提示词.md`
- `MAIN/写作与创作/文稿风格提示词.md` 是从一批 AI 稿反推出来的，只借它讲「开头」和「具体」的两节，别的地方以上面两份为准。

风格提示词和别的写作规范冲突时，听风格提示词的。例如 `human-writing` skill 禁用破折号，而他的书面语里破折号和括号是招牌——这是他的声音，不是模型腔。`human-writing` 只借它两条纪律：材料不够不灌水、事实要核。

**口播 / 视频稿：先读 `references/video-layer.md`，文字和画面一起写。** 写每一段之前先定这段观众看什么，再写这段的字——画面能承担的嘴就不说，该对着镜头说的不盖画面，连续四十秒想不出可看的东西就回素材里找一个具体的例子换进来。标注用那份文档里规定的 callout（`> [!节奏]`、`> [!画面] 类型｜内容｜怎么来`、`> [!声音]`），写在它管的那段话上面。写稿阶段只标注、不生成画面。

长文只标配图位（`> [!配图]`），见那份文档最后一节。

口播稿按 280 字 / 分钟算时长。稿子开头的字数、时长和情绪线里的时间不要自己估，写完跑检查脚本，照它报的实测值填。拿不准的年份和数字不要写进正文，挪到文末「录制前速查」。

### 6. 自查，然后存

先跑机械检查，它查能数出来的东西（时长、每节字数、翻案句、加粗过多、碎成一行一段、设问和 devil's advocate 有没有、画面空白、强度曲线的峰值位置）：

```bash
python3 ~/.claude/skills/koubo-writer/scripts/script_lint.py 稿子.md            # 长文加 --form article
```

报出来的每一条都要处理：改掉，或者有理由就保留并在交稿时说明（比如某段就是该对着镜头说，补一条 `出镜` 标注）。然后人工过一遍脚本查不了的：

- 那处暴论够不够敢；devil's advocate 是真在压测论点，还是摆设
- 每个判断后面有没有具体的东西撑着；撑着它的是他的素材还是你补的通识——补的要标出来
- 摘录有没有被写成他的亲身经历
- 每条画面标注在干哪件事（证明 / 解释 / 带入场景 / 换气）；说不清的是装饰，删掉
- 实际写出来的强度曲线和方案里的情绪线对不对得上
- 读出声顺不顺（长句有没有一口气说不完的）

口播 / 视频稿在末尾补上分镜表（用脚本生成，不手写）：

```bash
python3 ~/.claude/skills/koubo-writer/scripts/script_lint.py 稿子.md --shotlist   # 贴到「## 分镜与素材清单」下面
python3 ~/.claude/skills/koubo-writer/scripts/script_lint.py 稿子.md --clean      # 提词版：只有要念的字，他要的时候给
```

存到 `DRAFTS/<标题>_口播稿.md`（长文用 `<标题>.md`；已有同名的加 ` v2`、` v3`，不覆盖）。属性：

```yaml
---
选题: "<选题页名>"
形式: 口播稿
日期: 2026-10-02
作者: AI 初稿          # 他自己改过、认领之后再去掉这一行
素材:
  - "[[2025_11_04]]"   # 实际用到的每条素材所在的笔记名
---
```

`作者: AI 初稿` 这一行很重要：以后检索到这篇稿子时，能知道里面的句子不是他的原话。

然后更新主库里的选题页属性（只动这三项，别的不碰；键已经在就往列表里加，不要重复）：

- `稿件:` 加上这篇稿子相对 DRAFTS 根目录的路径
- `用到的素材:` 加上用到的 `[[笔记名]]`
- 不用手改 `状态`，选题台看到 `稿件` 会自己推到「成稿中」

最后重跑索引，选题台才认得新稿子：

```bash
bash "$HOME/Library/Mobile Documents/iCloud~md~obsidian/Documents/马自立/scripts/index-obsidian-vault.sh"
```

### 7. 交稿时说什么

稿子路径、字数和时长、检查结果（脚本报了什么、怎么处理的）、哪几处是你补的通识（请他核对或换成自己的话）、哪几节因为缺料写短了或没写、画面里有几条是「待找」和要专门做的（插画、动效）。不要复述稿子内容。

他确认稿子之后才做画面：解释图用「古典式」插画 skill，字卡动效、库存素材、AI 画面用 ChatCut 对应的 skill。稿子没定就做图，一改稿图全废。

## 改稿

他给了修改意见：先弄清是改内容、改声音还是改节奏。改内容回到第 2、3 步补料；改声音回到风格提示词对照；改节奏（「中间太平」「开头不抓人」「这段没东西看」）回到情绪线，先改那张表再改字。改完重跑检查脚本，分镜表重新生成。他反复提的同一类意见（比如「这句太像 AI」的具体句式），问他要不要写进对应的风格提示词——那是这套流程的长期记忆。
